# Export coverage matrix

This matrix accounts for all 101 registered resource types in the pinned PingOne provider v1.24.0 catalog. Registration means the type is known to the exporter; it does not prove a tenant can read it, that its import/read path works against every tenant, or that the imported state reproduces every original choice.

## Status and evidence

- **Recipe** means an explicit allowlisted API inventory recipe exists and the local inventory fixture suite exercises every recipe with at least one step. The downstream pinned provider import/read and schema renderer are implemented, but resource-specific live import/read validation is not claimed.
- **Limited** means discovery or import has a documented constraint stated in the row.
- **DaVinci** means this type is handled by the existing DaVinci source, not by `inventory_recipes.json`. Local exporter and composite tests use fixtures; tenant validation is not claimed.
- **Excluded** means registered in the provider catalog but disallowed by the shared resource catalog because it contains user data or user assignments.

Evidence references: [`resources.json`](../internal/resourcecatalog/resources.json) is the complete catalog; [`inventory_recipes.json`](../internal/exporter/inventory_recipes.json) defines each REST traversal, import template, filter, or limitation; [`inventory_test.go`](../internal/exporter/inventory_test.go) contains `TestInventoryEveryRecipeWithConfigurationFixtures`, `TestInventoryManifestAccountsForEveryAllowedNonDaVinciType`, and boundary tests; [`core.go`](../internal/exporter/core.go), [`composite.go`](../internal/exporter/composite.go), [`graph.go`](../internal/exporter/graph.go), and [`providerreader.go`](../internal/exporter/providerreader.go) implement import selection, dependency closure, and provider-backed state reads. Neutralization is generic (`internal/neutralize/neutralize.go`, `rewrite.go`, `render.go`) and covered by `internal/neutralize/neutralize_test.go`; it is not a per-resource-type rules registry. These are local fixture and implementation evidence only. No live PingOne tenant or hosted full-export validation is claimed.

## Cross-cutting limits

The inventory performs configuration-only reads, uses explicit recipes, and fails on inventory errors such as enabled-service 403/404 responses rather than treating them as empty collections. Image lookup and generated-secret resources have the constraints documented in the recipe manifest and ADR. The provider reader imports each selected object into disposable local state and renders from provider schema/state; it does not run `plan` or `apply`. Optional or unavailable source secrets can still make provider reads fail or require downstream secret inputs. Dependency discovery is bounded to the selected inventory graph and errors on unresolved ambiguity.

The 83 ordinary executable recipe entries have deterministic local HTTP fixtures; one image entry is lookup/reference-only, while three types have explicit no-importer reasons. DaVinci fixture coverage is maintained separately. These tests validate local traversal, classification, import-ID construction, graph behavior and neutralization transformations. They do not validate live permissions, service entitlements, tenant-specific API response behavior, complete cross-service dependencies, or exact source-configuration round trips. A hosted full export remains unverified.

## Core deployment bindings

Core neutralization now has explicit path rules in `internal/neutralize/core_lift.go`, with tests in `core_lift_test.go`: application redirect/logout and SAML/WS-Fed bindings, IdP endpoints/client identifiers, domains, certificate inputs, gateway directory/RADIUS/Kerberos settings, FIDO relying-party IDs, email/phone delivery endpoints, risk network allow-lists, and webhook endpoints. Schema-sensitive literals and existing variable references become required sensitive inputs with no source values, including nested maps/lists. Unsupported derived credential expressions fail closed. Environment name, type, region, license and immutable solution/service-tag bindings are per-environment values; copying the source environment's SANDBOX type or name into production is not permitted.

Graph-generated unknown reference inputs are explicitly marked environment-local through composition and neutralization; values from temporary source tfvars cannot cause connector IDs to be inlined again. Known excluded dependencies refer to an existing Git block or per-environment ID variable. See independently authored `core_review_regression_test.go`. Unknown-reference names currently include a source-value digest, so switching source environments can introduce additional required variables; they are not silently deleted.
